# World camera contributor notes

The [sample README](../samples/world-camera/README.md) covers the experience and controls.
This page keeps the editing and validation commands separate.

## Source files

- [World YAML](../samples/world-camera/levels/showcase/world.yaml): geometry, prefabs, actors and lights.
- [Level manifest](../samples/world-camera/levels/showcase/level.toml): materials and bake settings.
- [Camera controller](../samples/world-camera/src/cameras.go): walking, turning, panning and zooming.
- [Actor components](../samples/world-camera/src/actors.go): accepted-pose followers and animation.
- [HUD](../samples/world-camera/src/hud.go) and [controls](../samples/world-camera/ui/views/controls.kui): camera feedback and interaction.

From the sample directory, run `../../dist/karty schema` to refresh YAML editor
completions, or `../../dist/karty schema --check` to validate without processing
images or lighting. See [world YAML schemas](level-yaml-schema-v1.md).

## Artwork and lighting

The level uses source v8 with SDK 0.0.11: wall bands, independently mapped secondary colour, static solids, reflectance and liquid animation. Ordinary
`wall-top.png` and `wall-bottom.png` textures are declared in `level.toml`.
The 128×32 strips cover 2×0.5 metres, matching the main wall's texel density and
brick proportions. Alpha removes whole inner-edge bricks to reveal the main wall.

Room `wall_bands.top` and `.bottom` select a texture, height and repeat width;
edge `bands` overrides those defaults. The compiler resolves placement and UVs,
generates normal/height/AO and coverage-aware mipmaps, and packages the same
paired material atlases. Bands follow visible solid spans, including slopes and
stair risers; internal decomposition edges receive no bands.

Regenerate the checked-in textures from the CLI root:

```sh
mise run generate-world-camera-materials
# Replace only the court wall, preserving other custom artwork:
mise run generate-world-camera-materials -- --only z-court-plaster
# Regenerate each corridor band:
mise run generate-world-camera-materials -- --only wall-top
mise run generate-world-camera-materials -- --only wall-bottom
```

The level enables an offline bake with four samples, one indirect bounce and
medium denoising. Its six authored chunk areas retain the complete courtyard.
From the sample directory, run:

```sh
../../dist/karty dev
```

Every build packages a complete baked lightmap with each child mesh. Chunk builds
do not consume the whole-world `.karty/bakes/showcase/` cache or bake at runtime.
The moving corridor light is evaluated live and stays out of `[lightmap].lights`.
See [lightmaps](lightmaps.md) for quality settings and supported lighting behavior.

## Camera and renderer settings

Both cameras read resolution and projection settings from
[the project manifest](../samples/world-camera/karty.toml). KartUI stays at display
density. Camera render sizes are bounded to 1280×720; perspective uses vertical
FOV and isometric uses `ortho_height` in world units.

The player panel contains destination and camera controls, plus orbit/zoom/center
buttons for isometric. Renderer/lightmap and material-channel buttons are omitted.
Developer shortcuts remain: **I** shows accepted host poses, **G** cycles output
channels, **Z/X** follows the authored diagnostic route, and **R** remounts the
level. **Escape** releases capture and clears motion; **C** hides/restores controls.
Touch users can restore hidden controls by tapping the upper edge of the scene.

The court has sixteen rectangular bays, eight columns and a rounded rectangular
basin assembled from separate ledge and rim blocks. The ledge is 0.10 high, the
rim 0.44, the mosaic bottom 0.16, and the water rests at 0.36 with ±0.035 waves.
Its fixed sides and bottom use a zero-opacity binding. Polished floor materials use Materialize's `marble`
preset with zero metallic scale. Their reflectance produces highlights from the
baked irradiance; mirrored scene reflections apply to liquid.

`z-detail-grain.png` is a colour-only secondary layer generated by the tracked
artwork generator. It modulates the galleries and court with independent repeat
scales. Twenty-two static lights replace the six broad sources; they are selected
for the offline bake. The existing moving gallery light remains live.

Three bronze braziers hang over the basin from open iron chain links and a
crossbeam supported by the columns. Each bowl has separate rim pieces, straps,
emissive coals and a flame flipbook. Flame/coals artwork is copied from the
public Hangar sample. Their three warm light sources stay fixed in the bake.
The court contains 271 static solids; the complete sample has 355. Its authored mesh budget is 8 MiB;
lightmap density, the 1024 court page and the existing engine limits stay intact.

Seven slim wall torches occupy the gallery static-light stations. Narrow stems and low collars leave the flames unobstructed. The warm static lights sit above and just ahead of the holders, at radius 4.2. Their brackets, coals and fire share the hanging fixtures’ materials.

FPS touch input reserves the top toolbar and accepts the entire lower screen,
including below the authored game rectangle in portrait presentation. A floating
72-pixel joystick shows the clamped thumb position inside the visible scene,
including when the contact starts in the portrait letterbox; a 15% dead zone filters jitter
and diagonal movement remains normalized. Release, cancellation and input reset
hide the stick and stop movement.

Regenerate the basin and torch fixtures from the CLI root with
`mise run generate-world-camera-fixtures`. The marker-delimited prefabs and basin solids in
`world.yaml` belong to that tracked generator. Bronze and iron colour textures
belong to `generate-world-camera-materials`; use `-- --only z-hanging-bronze` or
`-- --only z-hanging-iron` to preserve other custom artwork.

## Focused behavior checks

From the CLI root:

```sh
mise run check-world-camera-components
mise run check-world-camera-hooks
mise run check-world-camera-geometry
```

The component fixtures cover typed hooks, mount/remount, camera movement,
accepted host poses and UI refresh without loading world assets, lighting bakes,
graphics or a browser. The geometry check executes the packaged level in WASM and verifies the solid basin heights, column identities, simplified portal graph and complete courtyard chunk ownership. Each test process is capped at nine seconds; compilation
and SDK setup are separate. See [sample validation](sample-development.md#focused-validation).

## Optional full-scene diagnostics

Build and serve the actual web sample from the CLI root:

```sh
mise run build-world-camera-web
mise run serve-world-camera -- --addr 127.0.0.1:4242
```

For the explicit full-scene check, supply matching checker/tool artifacts and
Playwright's pinned Chromium beside the browser checker:

```sh
KARTY_HOST_NATIVE=/path/to/karty-host \
KARTY_HOST_WEB=/path/to/karty-host.wasm \
KARTY_HOST_CHECK=/path/to/karty-host-check \
KARTY_WORLD_CAMERA_WEB_CHECK=/path/to/check-world-camera-web.mjs \
KARTY_TINYGO=/path/to/sdk-pinned/tinygo \
KARTY_WASM_TOOLS=/path/to/sdk-pinned/wasm-tools \
mise run check-world-camera
```

This builds clean authored inputs twice, compares staged bytes and executes the
packaged guest/level through native Wazero and the web host. It checks cameras,
movement, actors, remounts, corrupted-level containment and primary touch actions
at four viewport sizes. Web host overrides need their matching `wasm_exec.js`.
This is an explicit graphics diagnostic; manual device review remains separate.
